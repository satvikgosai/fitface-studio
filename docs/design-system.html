FitFace Studio — design system

The visual reference for :core:ui. Everything below is transcribed from FitFaceTheme.kt and FitFaceComponents.kt; those files are the authority and this page is stale if it disagrees with them. Implementation rules below cover copy, interaction, accessibility and known departures from the original design.

This file is self-contained on purpose. No build step, no server, no network: it has to render from a fresh clone on a plane. Do not add a CDN script, a webfont link or an external image to it.

Colour

One teal accent, three semantic hues, and a surface ladder that expresses elevation as lighter surfaces plus a 1dp border — never a shadow. warning and experimental are not part of a Material scheme, so FitFaceTheme provides them through LocalFitFaceSemanticColors; they carry different values per theme because the dark pair is unreadable on a light surface. The ratios below are against that scheme's own background, and SemanticColorContrastTest holds them to 4.5:1.

FitFaceTextColors supplies the two quiet tiers of text, and they are the only way to dim text in this app — there is no alpha to choose at a call site. secondary is meta lines, subtitles and section headings; tertiary is the quietest line where three stack up, as in a project row's name, source and age. Both clear 4.5:1 on every surface in both schemes, which SmallTextContrastTest holds. Disabled controls keep their own alphas and are exempt — a control that cannot be operated should look inert.

Type

Mono is not decoration. In this app the numerals are the content — a coordinate, a byte count, a sequence id — and a proportional digit changes width with its value, so a figure being nudged jitters while you hold the button. Anything quantitative goes in a mono slot. FitFaceType.readout exists because Material's ramp has no mono slot at 20sp, which is why the inspector's coordinates had fallen back to a proportional headlineSmall.

Shape, spacing, elevation

There is no spacing token. A FitFaceSpacing class encoding a 4dp scale used to exist and nothing ever read it, while the UI modules hold ~330 dp literals of which about two thirds are off that scale. It was deleted rather than left to imply a rule the code does not follow — see tokens and coverage. The values below are the ones actually in use; treat them as observed, not prescribed.

SHAPE — MaterialTheme.shapes
xs 4 sm 8 md 10 lg 14 xl 18

extraSmall is FitBadge's corner. extraLarge has no consumer, and a few places still hardcode RoundedCornerShape rather than reach for the token.

SURFACE ELEVATION — lighter, not shadow
base low container high

A card is surfaceContainerLow plus a 1dp outlineVariant border. There is no shadow anywhere in the app, and FitFaceElevation was deleted for having no consumers.

Components

Rendered against both schemes, because the semantic colours differ between them and that is exactly where a regression hides. Use the toggle to compare.

These are hand-built approximations, not a pixel-accurate render. The panels are 360px wide to stand in for a 360dp phone, but they draw with whatever sans and mono your browser resolves — Menlo or SF Mono on a Mac, which is materially wider than the Roboto Mono the device uses. Tokens and component structure follow the code; illustrative labels do not replace the app’s string resources, and text widths are not, so do not read a truncation or a fit off this page. The measured device figures are in the width-budget table below, and FitTopBarLayoutTest is what actually holds the line.

Glyphs

There is no icon library in this project and no vector drawable outside the launcher. Most symbols are text glyphs; nudge arrows and colour swatches are drawn. Resource headers record the inline glyph choice as deliberate: they are symbols, not copy, so they stay inline in the Composables where a translator will not see them. A glyph-only control needs a contentDescription — without one a screen reader announces the character, which is how the overflow button used to introduce itself as "midline horizontal ellipsis".

The top bar's width budget

The header width contract is checked by layout tests. FitTopBar gives its title/subtitle column a weight(1f), so the column is the flexible child and every dp an action takes comes out of the title. A full-label "Report a problem" TextButton took 109dp of a 360dp bar — wider than the title beside it — and the subtitle was silently ellipsized on every editor page, with no exception, no lint warning and nothing in any test.

This is also why the app's three global actions — report a problem, about, check for update — are one ≡ button and a menu rather than three buttons. There are two menus now — this one and a project row's — and they share FitDropdownMenu and FitMenuEntry, because assembled separately the second took Material's default entry type against this one's bodyMedium. A DropdownMenu is a Popup, measured in its own window, so the bar pays for the anchor and nothing else: the numbers below are the same as they were for the single button it replaced. FitTopBarLayoutTest.theOpenMenuCostsTheBarNoWidth is what keeps that true.

Two rules follow, and both have been broken here before. An action is a FitIconButton and its label lives in the contentDescription. The always-present action is emitted last, so as the final child its right edge pins to the padding and it stops sliding sideways when a conditional neighbour appears — the library's moved 189px on a tab switch. FitTopBarLayoutTest pins the budget; it asserts geometry rather than whether text was ellipsized, because Robolectric's font metrics are not the device's and a truncation assertion passes while a real phone still clips.

Screens

A page is a distinct task with its own state and its own way out, and earns a back-stack entry. A peek or sheet needs the canvas visible while you use it, or resolves in one tap — a 1px nudge needs the face in the same eyeful, so nudging is never a page. Five rail destinations means one back stack and no nested graphs.

Implementation rules

Current behaviour and constraints for contributors. Update this page with the Kotlin components; task audits and screenshots stay in ignored analysis/reviews/. AGENTS is the working brief; Architecture owns rendering and the format reference owns edit safety.

Copy and visible status

  • Keep action meaning, scope, size limits, shared-artwork consequences, warnings, errors and recovery visible. Use plain names; record/protocol facts belong in Inspector or labelled details.
  • Canvas shows EDITED in its header whenever snapshot.isDirty, alongside Project ⋯ and app menu ≡. Include edited status in the title's accessibility description. Background shows UNAPPLIED while an image is pending.
  • FitDetails is a 48dp-minimum full-header button with action label, announced expanded state and restored state. Tap, keyboard and TalkBack open the same content; long press is never the only route. Put long expanded content in the page/sheet scroll region so pinned actions stay reachable.
  • Use styleLabel from the parsed style number plus one, not a list index. Use variantLabel for AOD everywhere, including accessibility; raw sampler IDs remain protocol data. Removed rows retain typed category/model facts rather than preformatted technical labels, with defaults for older stored data.
  • A custom row contentDescription must include its identity and visible status, including OUTDATED. A no-outline widget's support reason appears once in its banner, not again in Record details.
  • Persistent failures have persistent state (catalogFailure); a sheet shows sheetError because it covers the snackbar. Await showSnackbar, then clear in finally: clearing the effect's key first cancels the message.

Headers, menus and dialogs

  • Top-bar actions are 38dp icon buttons with accessible labels. Keep the title column flexible and the always-present app menu last. Do not align a single action against the centre of a two-line title column. FitTopBarLayoutTest measures width and anchoring, not device truncation.
  • FitDropdownMenu/FitMenuEntry share typography across app and project menus. Popup contents cost no bar width. Close before callbacks; destructive entries use error colour and go last. ≡ means app actions; ⋯ means project actions (row menu or Canvas → Project). They intentionally coexist on Canvas.
  • Use rendered glyph samples on Android before adding symbols. ⚙/ℹ can become emoji, ❐ lost its duplicate shape and ␡ rendered tiny letters. Scope is ▤; nudge arrows are drawn paths, not font arrows with mismatched baselines.
  • Library tabs share one header/inset component. Measure the taller subtitle, retain the hidden one with alpha zero and cleared semantics, and keep the action floor at 48dp. Hidden import uses Refresh's slot on Projects. Crash tint and “Report crash” change wording/colour only, never geometry. LibraryHeaderLayoutTest covers both tabs and the developer flag.
  • Dialog text slots scroll once at the outer slot; nested scrolling still clips text above it. About stays short enough for landscape, with a one-sentence independent/non-affiliated statement, labelled version and project link. AboutCopyTest pins meaning/length; LinkAnnotation.Url uses the URI handler without a UI-layer Context/Intent.

Canvas and selection

  • Five rail destinations: Canvas, Widgets, Background, Styles, Install. Back leaves the editor; Canvas is a destination, not a hidden mode. Widgets is a picker: a single selection goes to Canvas, a set stays in the list. Inspector is secondary Record details. Navigate out of Inspector after a removal-count change, not merely a cleared selection.
  • SelectionActionBar has four drawn nudge arrows and seven actions: smaller, larger, duplicate, remove, colour, scope, details. Both rows fill width. Apply the icon button's size before the caller modifier so weight controls width while height stays 38dp; don't repeat the header's dimensions in the tray. Compact buttons serve this tray.
  • Scope defaults to selected style. Its toggle uses filled tint, border and glyph; colour alone does not communicate selection. Keep it visible but disabled for AOD, imported widgets and single-style faces. Colour menus show checkedLabel and close before action; use a drawn bordered swatch so black remains visible.
  • RepeatingNudgeButton needs a click fallback for fast taps and a repeated flag to avoid one extra step on release. EditorViewModelTest checks queued movement. Queue from pending/in-flight targets, never a stale snapshot; coalesce to the latest target. Restoring position must cancel outstanding movement.
  • Keep gesture inputs current with rememberUpdatedState; do not restart pointerInput on every snapshot. stepDragAxis accumulates unclamped finger travel and clamps only output, so returning from an edge stays under the finger.
  • Arrange layers is a labelled tap action on the single-widget tray and in Record details. Its scrollable dialog offers Bring to front, Bring forward, Send backward and Send to back, with selected-variant-only scope. Disable actions at boundaries and explain fixed full-face backgrounds. Close before the edit callback; refused alignment changes use the persistent editor error. Selection follows the moved widget. Host dialog state outside responsive content. The tray puts coordinates below the title/action row so three labelled icons do not truncate geometry.
  • Rotate widget is a labelled tap action on the single-widget tray and in Record details. Its dialog lives outside the responsive tray so an orientation change retains the pending angle. The scrollable body shows current/original angles and edit scope, accepts tenths of a degree, and offers 15-degree steps and Reset rotation. Apply commits the chosen angle; Cancel leaves it unchanged. Unsupported types explain the limitation. Keep the opaque black text backdrop and approximate-font limitation visible.
  • The first hold enters selection mode, including on the already-selected widget. Repeated holds keep an item selected; taps toggle membership. A remaining singleton stays in selection mode until Done returns it to ordinary editing. Clear, bare canvas or removing the final pick exits. The single-widget tray and widget rows provide labelled tap alternatives to holding. Widgets stays open while selecting, including one item; Edit on canvas opens the set controls. Set drag is disabled, including for one item. Nudge by the most constrained member's shared step. Duplicate/remove use single-widget calls, stop at first refusal and report committed results; remove highest index first.
  • Publish all visual set targets together in pendingSetMove; setMoveSegments preserves intervening z-order while individual commits finish. Keep the tray's height stable and unsupported set actions disabled.

Window size and scrolling

  • Fit the face to both available width and height; use split layouts in short windows. Rail labels have no tracking, and the vertical rail scrolls with tighter spacing. Weighted equal-height slots clip labels rather than solve overflow. EditorRailLayoutTest checks arithmetic.
  • In the wide editor, InstallWorkspace(showFace = false) avoids duplicating the side-pane face. Background keeps its interactive placement preview. Its zoom buttons step two percentage points on a fixed grid; pinch remains continuous.
  • Check narrow phones, landscape, large text, keyboard, sheets and expanded help on the emulator. The library can still be cramped in short landscape; do not infer full adaptive coverage from the editor's split layout.

Install and thumbnails

  • previewReviewed clears on every commit; InstallWorkspace's snapshot effect re-marks it. It arms sending, not a redirect to a separate Validate page. validatedBytes() remains the actual safety gate.
  • One read-only render belongs in the device card (80dp plate); status is on a line above the device name, not squeezed beside it. Checks and Audit sit directly below, above setup. Audit remains present when empty. Passing checks need no extra success banner; failed checks keep theirs.
  • Show transfer phase/percentage; put protocol messages, windows and payload IDs in Transfer details. Completion is Request sent, with watch inspection and plugin restoration instructions.
  • Styles owns face-picker thumbnail refresh. Compare stored before/after pictures, including actual RGB565 quantization and box-filtered output; don't compare against a scaled canvas pretending to be stored output. Refresh the active numbered style once per edit identity, clear the marker on an edit, and treat a no-op as null (ThumbnailPreviewTest). AOD refresh is refused in the repository.
  • Previews render current layers, ordered and alpha-correct; unavailable content is disclosed, never replaced by invented boxes. The preview pipeline defines sample readings, locale fallback and ROM-font approximations. Preview review does not establish watch-side acceptance.

Donor imports

  • Donor backgrounds: Background offers “From another watch face” beside image picking. Reuse the donor catalogue and variant labels, show only the primary background asset, and explain missing or additional full-panel artwork. Review is UNAPPLIED, renders the encoded result, has tap-accessible Before/After controls and lists both affected and skipped variants. Apply commits; back/cancel does not. Keep source/review errors in the picker and all content scrollable at large text or short height.
  • Style deletion: Each numbered style has a labelled Delete action. Manage styles shows current resource previews, exact bytes reclaimed, remaining numbering and active-style fallback before an explicit destructive confirmation. Keep at least one numbered style; AOD is separate and cannot be deleted. Explain that Reset restores all pristine styles while discarding other edits. Keep the selection and confirmation across orientation changes, with scrolling content and reachable actions.
  • Capacity recovery: Only typed BIN-capacity failures offer Manage styles; partial background additions offer it too. Protect the pending target style, retain image placement and donor picks, and regenerate Review after deletion. Do not re-add successful widgets from a partial batch. State that confirmed deletion was saved separately and cancelling the pending edit does not undo it. Errors remain in the dialog that owns them.
  • A full-screen child from Widgets, not a sixth rail tab. Reuse catalogue grid and shared components; no separate Projects tab. Say whether each donor is cached or requires download, and show unavailable widgets with refusal reasons in List.
  • Pick on the donor face with the editor's hit testing, or use rows for hands without outlines. Number picks in insertion/z-order. Selection offers Review widget(s); only the review's Add commits. Face size means used bytes. Single-ticket pricing is exact; sets say “at least” and retain partial-save consequences.
  • Review outlines additions, dims the rest and shows before while held. Both donor and review split on short height (importPageSplits, WidgetImportLayoutTest). Donor-position invariance and the batch commit contract live in the format reference.
  • Pricing must not block the next pick: gate picks on saving, not all busy work, and keep pricing progress in the button. Reserve the global progress strip so it cannot shift tap targets. Pick chips scroll on one line; meter/error text has a fixed two-line slot. pickError stays beside its action and clears on the next pick.
  • Variant changes keep the previous face visible until the replacement is ready; reject picks during that interval but leave variant chips usable. Show delayed loading after 300ms, not a flash per tap. Cancellation restores the shown variant label. Errors persist; preparation/download can cancel/retry; saving is single-flight.

Library

  • Sort by reversing the primary comparator only; keep stable tie-breakers. Opposite direction labels use equal-length monospace text, at most eight characters, to fit the 288dp content width of a 320dp phone (SortChipLayoutTest).
  • openingProjectId replaces only the selected row's chevron with a spinner, retains its opacity and dims others. Don't reserve spinner width on every idle row. Downloads gate on project opening; cached cards use canSelectFace, so background catalogue refresh cannot silently disable them.
  • Project rows in the scrolling face sheet use a Column, not a nested vertical LazyColumn. Source, stored project name and age remain distinct; custom descriptions announce outdated status. Updates create another project. “No download” promises come from hasPackage, not a row's existence.

Tokens, departures and coverage

  • Platform SansSerif/Monospace replace the original Plex design; no font files are bundled. Quantities use mono labels/numeric/micro/readout (20sp). Font changes require a fresh device layout pass.
  • Spacing is expressed by literals; unused spacing/elevation token classes were removed. Elevation uses surface colour and a 1dp border, never shadow. Tokenizing spacing or enlarging touch targets is a separate layout change, not an incidental cleanup.
  • Known touch-target compromise: icon actions are 38dp and chips 42dp against the 48dp guideline. FitDetails has a 48dp minimum. Preserve consistency until an app-wide size change is tested.
  • FitFaceSemanticColors must be provided per theme: warning/experimental once fell back to dark colours on light backgrounds (1.50:1/1.73:1); light roles now measure 6.07:1/6.27:1. SemanticColorContrastTest checks values; FitFaceThemeTest checks the provider.
  • Use MaterialTheme.fitText.secondary and tertiary without call-site alpha. Recorded secondary contrast is 6.52:1 dark / 6.67:1 light, tertiary 5.56:1 / 5.27:1. Extra dimming formerly reduced micro text to 4.08/3.38 and project age to 2.58. Tertiary derives from onSurfaceVariant × .90 for margin; .82 barely passed at 4.52. SmallTextContrastTest holds the 4.5:1 floor on all surfaces. Disabled controls retain their treatment.
  • Open typography issue: 11sp Medium mono teal actions have 12.77:1 contrast but can still be too small; changing colour does not solve size. Micro labels are 9.5sp. Browser demos approximate phone dimensions, not Android text metrics.
  • Native Robolectric checks geometry and expandable-help semantics, not device truncation. AlertDialogs can fail to idle in that harness; gesture wiring and updater dialogs need emulator checks. Development records precise coverage limits.
